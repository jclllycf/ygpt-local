# Changelog

## Unreleased

- Update package + strip preview (candidate 1.0.0-rc.12): releases now also ship `YGPTLocal-Update-<version>-win-x64.exe` for owners who already have YGPT Local installed — no uninstall, no re-provisioning, no ChatGPT plugin changes. The updater finds existing installations (uninstall registry, then the default locations), shows installed → new version, pauses the owned connection, swaps the payload in place (data folder, credentials, connection identity and snapshots untouched), saves the brand choice and restarts the connection, verifying the watchdog heartbeat before declaring success. It is the same binary family as Setup: update mode is entered via `--update` or an exe name containing "Update" (new `setup/UpdateWindow.cs`). The icon/style picker in both the wizard and the updater gains a live approval-strip preview — a native mock for the new strip (the icon follows the selection) and a faithful screenshot of the real classic strip (`assets/brand/preview-classic.png`, regenerable via `scripts/make-preview.mjs`, embedded as a resource).
- Approval strip: owner's icon + classic style option (candidate 1.0.0-rc.11): the in-chat approval strip no longer carries the old inline SVG redraw — at serve time it inlines the owner's chosen icon (data URL; the strip CSP allows no external images). The setup wizard's Welcome step gains a "Make it yours" card: five icon editions (current sprout, first-design green Y, Sky Air Y, RC3 green, signature) and two strip styles — the new strip (follows the chosen icon) or the classic strip, the original project's approval bar restored verbatim from the baseline as `runtime/approval-bar-legacy.html` (same y_bar_decide/y_bar_status contract). The choice persists in ygpt.config.json (brandIcon / approvalStyle), survives re-provisioning, and is preselected when Settings reopens. Covered by tests/brand-choice.test.mjs.
- Upgrade-over-install fix + icon cache (candidate 1.0.0-rc.10): installing over an existing folder (the rc.9-over-rc.8 field failure, "Access to the path 'D:\\YGPTLocal' is denied") now retries the directory swap for a few seconds (outgoing processes and antivirus scans release the folder on their own schedule), cleans up its staging folder on failure, and otherwise fails with an actionable message (exit the tray app or restart, then rerun Setup; no files changed, private data untouched) instead of a raw .NET error. Setup also nudges the Windows icon cache after install (SHCNE_ASSOCCHANGED): the cache keys one rendering per app path and kept serving the old low-resolution icon after upgrades — the shipped .ico itself was verified entry by entry (7 true-size PNG frames; the 256 frame is pixel-identical to the HD master render). The wizard version label finally tracks the release (it had been frozen at rc.3 in HostCore). Restored keepsakes: the first-design green "y_" and the Sky Air blue "y_" 256 PNGs return to the brand folder and the installed picker set.
- One icon spec (candidate 1.0.0-rc.9): every shipped standalone icon is now 256x256 and at most 10 KB (the plugin form's limit) while staying crisp — one canonical palette-optimized PNG (9,866 bytes, from the HD master) serves as the brand 256, the plugin icon, `assets/png/icon-256.png` and the plugin logo; the green and signature keepsakes are 5,512 / 8,776 bytes. The loose multi-size PNG files are retired: the Windows .ico files still carry their 16-256 frames, generated in memory by `scripts/make-icons-from-original.py`. This also restores the repo's own brand check (`ygpt-local-256.png` must be <=10,240 bytes), which the un-optimized HD render had exceeded at 26 KB.
- Picker folder + tunnel name (candidate 1.0.0-rc.8): the suggested Tunnel name is now just `YGPT Local`. The installed `assets/brand` folder (the plugin-icon picker the setup wizard opens) is pruned at packaging time to three files — `plugin-icon-256.png` (current sprout, palette-optimized to 9,866 bytes for the under-10 KB plugin form), `ygpt-local-green-256.png` (the RC3 green keepsake, recovered from the candidate sheet) and `ygpt-local-signature-256.png` (the First Light signature keepsake) — and the glyph masters are no longer staged into the install.
- Crisp original artwork (candidate 1.0.0-rc.7): the extracted glyph is only ~113 px, so the shipped icons read blurry at large sizes. The glyph is now rebuilt as an opaque master directly from the owner's board art (silhouette from distance-to-white, colours are the original pixels) and re-rendered at 16x with re-hardened edges and fringe decontamination (`scripts/make-glyph-hd.py` -> `assets/icon-glyph-hd.png`), so every size is crisp while the shape and gradients stay 1:1 with the original. The glyph also sits lower in the tile now (optical centre ~51%), fixing the "rides too high" balance.
- Original artwork + setup defaults (candidate 1.0.0-rc.6): the shipped icon set is now composed from the owner's original sprout artwork, extracted pixel-for-pixel from the brand board into `assets/icon-glyph.png` and regenerated by `scripts/make-icons-from-original.py` (the vector redraw read too flat next to the original). Fresh installs now default to a non-system drive when one exists — install `D:\YGPTLocal`, data `D:\YGPTLocalData` — so the runtime, state, snapshots and backups stay off the system drive (AppData defaults remain the fallback; explicit folders always win). The setup rail's "YGPT Local" title is deep ink again instead of near-white on the pale rail.
- Owner blacklist permission model (candidate 1.0.0-rc.5): default allow, restrictions as human gates instead of refusals. The file and terminal engines accept absolute paths on any volume (relative paths stay inside the engine root), so an application config folder on C: (e.g. Clash Verge under AppData) can be edited directly once policy allows it — no per-app enrollment; policy still gates system and credential-adjacent targets and refuses only YGPT's own runtime/state/credentials and the G: vault. `y_file_trash` is tiered: a single ordinary file deletes by default with a verified protected snapshot first (snapshot id = rollback handle), while batch, directory and system deletes require a human decision. The document-format hard refusal is removed, downloads outside project folders gate instead of refusing, and bulk-delete command shapes (wildcards, `Get-ChildItem | Remove-Item` pipelines) are detected as high-risk. Verified by `tests/owner-model.test.mjs`; production stays on rc.2 until the owner switches it.
- Chat-only isolation upgrade (candidate 1.0.0-rc.4, branch `upgrade/chat-only-isolation-20261022`): YGPT serves ordinary ChatGPT chats only, with per-chat resource ownership (tabs, UIA bindings, processes, jobs), a hard Desktop Agent boundary, Desktop UIA kept available with human approval by default, per-file write locks with `expectedSha256` conflict errors, and Unknown-never-replayed recovery. The legacy compatibility surface is deleted — one canonical typed `y_*` API remains (66 tools served, 64 model-visible); retired names answer `NO_TOOL` with their replacement. New tools: `y_file_read_many`, `y_file_patch`, `y_project_inspect`, `y_file_trash`, `y_usage_report`, `y_resource_owner`. Records: `docs/UPGRADE_TOOL_MAPPING.md`, `docs/UPGRADE_SECURITY_NOTE.md`, `docs/UPGRADE_TEST_RESULTS.md`, `docs/UPGRADE_USER_GUIDE.md`. Production stays on rc.2 until the owner switches it.
- Merged the RC3 line (GitHub main 6f1f9e1: secure tunnel fixes, split setup architecture `HostCore`/`SetupWindow`/`Watchdog`/`NativeWindows`, RC3 runtime and service hardening) with the local design line (First Light + sprout brand). The RC3 wizard now speaks First Light: light rail and canvas, sky action colour, attention-ink errors, and the sprout mark as its brand image and exe icon (`assets/brand/ygpt-local.*` regenerated from `assets/icon.svg`). Approval surfaces (in-chat card, owner page, native popup) remain the First Light versions. The pre-merge monolith wizard remains in history at c30c4dd.
- New brand icon: the sprout Y, two leaf arms in a sky gradient with a rising sun above the fork, on a white tile. It has a dedicated 16-24 px cut. The icon set, the exe and tray icon, the setup wizard, the native and in-chat approval cards and the owner approval page all carry it.
- YGPT brand mark and icon set (`assets/icon.svg`, `assets/ygpt.ico`, plugin logo), generated by `scripts/make-icons.mjs` and embedded in `YGPTLocal.exe`, `YDesktop.exe` and the installer.
- Restyled the setup wizard (inputs, buttons, consent callout, connection cards, sidebar mark and step badges). The approval popup now uses the same green identity. No behavior or copy changes.
