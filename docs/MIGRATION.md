# Updates and state preservation

Use the current Update executable for an existing installation. Finish active work and decide pending approvals before maintenance. The updater preserves the selected installation identity, credentials, private data and snapshots, and verifies the new payload before switching runtimes. Data stays below the selected installation root.

YGPT serves one typed tool catalog. Removed names have no executable routes or replacement aliases. Refresh tools/list or the plugin connection after upgrading. Use current names from the live catalog and plugin/skills/local-work/SKILL.md; historical tool-migration plans are excluded from installed packages.

Existing operation history is retained for audit and recovery. A saved old tool name is a past event, not an installed tool. Unknown operations are never replayed. Old approval resource addresses can serve the current component for already-rendered cards; they expose no old tools or permissions.

Do not merge browser profiles, account homes or unrelated installations. Private data is not ordinary cache. Restore checks expected hashes and preserves conflicting newer changes.
