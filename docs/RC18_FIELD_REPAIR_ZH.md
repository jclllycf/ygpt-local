# rc.18 实机修复与交付

2026-10-23。本文取代旧 rc.3 / rc.17 文档中的当前版本与默认目录说明；历史记录保留。

## 现场确认

- GitHub `main` 的 rc.17 与原安装版可对应的 82 个文件一致，没有额外本机源码修改。
- 原安装确实把数据放在程序目录外。现已迁入所选程序目录的 `data`，外部旧目录不再存在。104 个内部缓存联接完成重定位。
- 连接配置、DPAPI 凭据、状态密钥和扩展配对文件经 SHA-256 比较保持不变；未重建 Tunnel、未重配 ChatGPT 插件。
- 更新恢复后，本机引擎与 Tunnel 为 Ready；启动任务使用内部数据路径。安装清单 5,848 项校验无差异（第一次 rc.18 实机部署）。最终打包项数可能因交付文档增加而变化。
- UIA 测试程序的登记哈希已与更新后的实际 EXE 一致。Windows 集成测试实际启动了无害测试窗口，并验证绑定、输入、点击、拒绝与结果读取；测试中的批准来自受控 fixture，不代表真实用户点击。

## 目录约定

```text
用户所选 YGPTLocal/
  YGPTLocal.exe
  YGPTWatchdog.exe
  runtime/  runtimes/  engine/  service/  extension/  assets/
  data/       配置、加密凭据、状态库、历史、文件快照、临时浏览器文件
  .updates/   暂存、上个版本的程序成员、本机恢复资料
```

新安装的数据路径随所选程序目录生成；自定义安装位置不会借用另一份默认安装的数据。更新不再移动整个安装根目录，而是只替换程序成员，保留内部数据与未知用户文件。迁移拒绝未知联接、重叠目标和属于其他安装的数据；不合并两份数据。

Windows 的开始菜单快捷方式和任务计划注册是操作系统集成项。源代码开发目录、用户自行下载的安装包及已授权的项目文件不属于安装数据目录。

## 浏览器

- 隔离 `y_browser_open` 默认一次读取，返回快照前关闭浏览器并删除临时 Profile。结果带 `closedAfterCall: true`，不能再使用这个临时 tabId。
- 明确需要多步交互时设置 `keepAlive: true`，后续操作保留原 `contextToken`，结束时在 finally 路径关闭标签页。最后一个标签页关闭时立即退出浏览器；30 秒空闲租约兜底释放。导航和上下文创建失败也清理。
- 日常浏览器每个配置文件使用独立 CDP 中继，每个对话独立选择配置。多个配置可同时工作；相同 Chrome tabId 不会造成跨账号控制。只操作 YGPT 分组，用户浏览器和个人标签页保留。
- 可在扩展弹窗填写易懂的 Profile label；不依赖 Chrome 登录邮箱识别未登录配置。

**本次唯一的浏览器手动步骤：** 两个已加载的旧版 unpacked YGPT 扩展需要各重新加载一次。在对应 Chrome/Edge 配置中打开扩展管理页，找到 YGPT Local，点 Reload。配对令牌不必重填。其他尚未安装该扩展的配置仍需由用户首次安装、配对；程序不会偷偷复制浏览器账户或修改 Chrome 的配置文件。更新后的扩展通过版本协商处理后续资源重载，避免无限重载。

## 授权条与图标

授权条同时修复 `img-src` 禁止内嵌图片和 Windows 换行导致 CSP 哈希失配的问题；新版资源 URI 促使宿主重新取资源，旧 URI 继续提供修正后的页面。真实 Edge 测试确认图片正常解码、脚本样式无 CSP 拦截，批准/拒绝 fixture 能工作。

应用使用完整色彩的 256 / 512 / 1024 PNG 和 16 / 24 / 32 / 48 / 64 / 128 / 256 七档 ICO。四款几何历史图标具有矢量源与高清输出。快捷方式使用带版本号的 ICO 路径以避开旧缓存。**只有 `assets/brand/plugin-icon-256.png` 是插件表单专用压缩文件，本次为 4,053 字节。** 应用和授权条不再使用该压缩文件。
