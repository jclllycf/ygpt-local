# 权限与当前聊天 Full Access

普通模式下，所有有效本地路径的结构化读取直接放行，包括受保护目录；实际访问仍受当前 Windows 账户权限限制。普通修改保留写前快照。小规模清理通过 `y_file_trash` 自动执行：最多 64 个条目、16 MiB，或单个不超过 32 MiB 的普通文件；删除前必须验证恢复快照，并移入 Windows 回收站。

敏感文件修改、大规模删除、系统或提权操作、桌面点击与输入仍需授权。窗口列表、绑定、检查、聚焦可直接执行。脚本与命令默认放行，仅在识别出明确高危信号时要求授权。未知脚本、局部变量、循环、动态或编码代码、多行参数、受保护目录引用，本身都不是授权理由。未知代码获准运行，不代表系统已证明它只读或安全。

内置 Node、npm、npx、Python 仅在安装清单中的精确路径、大小和 SHA-256 一致时被视为可信可执行文件，其参数仍要检查。同目录的其他程序不会获得信任。

## 为一个开发聊天开启 Full Access

1. 在需要的聊天里说：**为当前聊天申请 120 分钟 Full Access。** 对应工具为 `y_chat_access`，`action: "request_full"`；可选 `durationMinutes` 为 1–720，默认 120。
2. 检查专用卡片 **Enable Full Access for this chat**，点击 **Enable Full Access** 开启，或点击 **Deny** 拒绝。模型参数或普通文字回复不能直接开启此模式。
3. 仅在本聊天保留返回的 `contextToken`，后续 YGPT 调用继续携带。通过 `y_chat_access` 的 `action: "status"` 或 `y_policy` 查询状态与到期时间。
4. 使用 `y_chat_access` 的 `action: "revoke"` 退出；`y_close_context` 也会撤销权限，并释放本聊天的浏览器和桌面绑定。

开启期间，本聊天可以直接读取私人文件、修改文件、运行命令、操作桌面窗口，不再反复触发 YGPT 策略授权。其他聊天保持普通权限。此前等待批准的操作仍保持等待；开启模式不会自动执行它们。已经批准的操作应读取原结果，不能重复执行。

该模式不会取得 Windows 管理员权限。参数、路径、修改前哈希、任务结果令牌、资源归属和引擎限制仍有效；不能接管其他聊天创建的标签页、窗口、进程和任务。撤销对后续权限检查生效，不会取消已运行的进程或撤销已完成的修改。续期需要再次明确点击专用卡片。

聊天上下文是服务端签发的能力令牌，并非经过认证的 OpenAI 对话身份。不要跨聊天复制令牌，也不要写入公开日志或 GitHub。服务重启后，仅当原上下文仍有效时，授权才可继续到原定到期时间。如果宿主没有报告聊天关闭，固定到期时间与显式退出操作承担结束边界。

手机端不显示卡片时，可在 ChatGPT 网页端打开同一聊天，或使用电脑上的 Windows 手动授权中心。卡片缺失不会开启 Full Access，也无需新增公网授权服务。
