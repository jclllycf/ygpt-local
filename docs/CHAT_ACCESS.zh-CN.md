# 权限与当前聊天 Full Access

普通模式下，所有有效本地路径的结构化读取直接放行，包括受保护目录；实际访问仍受当前 Windows 账户权限限制。普通修改保留写前快照。小规模清理通过 `y_file_trash` 自动执行：最多 64 个条目、16 MiB，或单个不超过 32 MiB 的普通文件；删除前必须验证恢复快照，并移入 Windows 回收站。

普通模式下，敏感文件修改、大规模删除、系统或提权操作仍需授权。窗口列表与本聊天已绑定窗口的检查自动放行。首次桌面绑定或输入仅申请一次当前聊天的 100 分钟 Full Access；期间所有桌面窗口、文件和命令无需重复授权。其他聊天不继承。脚本与命令默认放行，仅在识别出明确高危信号时要求授权；未知脚本、变量、循环、动态或编码代码、多行参数和受保护目录引用本身不是授权理由。

内置 Node、npm、npx、Python 仅在安装清单中的精确路径、大小和 SHA-256 一致时被视为可信可执行文件，其参数仍要检查。同目录的其他程序不会获得信任。

## 为一个开发聊天开启 Full Access

1. 在需要的聊天里说：**为当前聊天申请 120 分钟 Full Access。** 对应工具为 `y_chat_access`，`action: "request_full"`；可选 `durationMinutes` 为 1–720，默认 120。
2. 启用请求直接在当前对话返回 **Enable Full Access for this chat** 卡片，点击 **Enable Full Access** 开启，或点击 **Deny** 拒绝，无需转到 Windows 设置。只查询状态不会发起启用请求；模型参数或普通文字回复不能代替卡片确认。
3. 仅在本聊天保留返回的 `contextToken`，后续 YGPT 调用继续携带。通过 `y_chat_access` 的 `action: "status"` 或 `y_policy` 查询状态与到期时间。
4. 使用 `y_chat_access` 的 `action: "revoke"` 退出；`y_close_context` 也会撤销权限，并释放本聊天的浏览器和桌面绑定。

开启期间，本聊天可以直接读取私人文件、修改文件、运行命令、操作桌面窗口，不再反复触发 YGPT 策略授权。其他聊天保持普通权限。此前等待批准的操作仍保持等待；开启模式不会自动执行它们。已经批准的操作应读取原结果，不能重复执行。

该模式不会取得 Windows 管理员权限。参数、路径、修改前哈希、任务结果令牌、资源归属和引擎限制仍有效；不能接管其他聊天创建的标签页、窗口、进程和任务。撤销对后续权限检查生效，不会取消已运行的进程或撤销已完成的修改。续期需要再次明确点击专用卡片。

聊天上下文是服务端签发的能力令牌，并非经过认证的 OpenAI 对话身份。不要跨聊天复制令牌，也不要写入公开日志或 GitHub。服务重启后，仅当原上下文仍有效时，授权才可继续到原定到期时间。如果宿主没有报告聊天关闭，固定到期时间与显式退出操作承担结束边界。

手机端不显示卡片时，可在 ChatGPT 网页端打开同一聊天，或使用电脑上的 Windows 手动授权中心。卡片缺失不会开启 Full Access，也无需新增公网授权服务。

## 桌面任务与截图

如果卡片显示 **Refresh approval**，或工具返回 `APPROVAL_CONTEXT_*`，说明原上下文缺失、不匹配或已过期。不要继续点击或等待这张不可用卡片。应让模型从同一对话找回原请求一起返回的 requestId、resultToken、contextToken，只刷新授权卡。原上下文丢失时，由你本人在 Windows 授权中心处理保存的请求，不能重放桌面操作或借用其他聊天的上下文。

首次桌面操控卡明确申请 100 分钟 Full Access，确认后只执行此次请求一次。期间后续窗口绑定、点击、输入、快捷键和命令复用授权。此前其他待定请求不会自动重放；到期或撤销后，下一次输入先暂停等待续期。`y_desktop_action action=keys` 支持 `CTRL+L`、`CTRL+T`、`ENTER` 等快捷键，仍须核对控件、原生错误和结果是否不确定。

桌面操控主要读取 Windows 控件树，截图是独立图片观察。生成的 PNG 以内联图片发送，返回前删除本地文件；本地结果历史保留元数据，不保留图片内容，启动时回收过期的程序截图。其他图片、凭据与快照保持完整。已经传给 ChatGPT 的图片遵循宿主保留规则。

组合键一次发送完整的按下与松开序列。输入失败保留 inputDiagnostics：请求/实际送入的事件数量、Win32 错误和进程完整性级别。返回零本身不能证明 UIPI 拦截，见 [Microsoft SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。INPUT_INTEGRITY_MISMATCH 在输入前确认目标权限更高；其他错误不能据此反复申请授权或自动提权。部分输入成功、或此前已输入后再失败时，结果仍可能不确定，应核对窗口与键盘状态，不能重放操作。服务重启后需要重新选择并绑定当前窗口，旧桌面 targetId 不会恢复。

先显示当前授权卡，再用 `y_wait_approval` 进行有界等待，保持原任务待处理，确认后自动返回已有结果继续。每次渲染使用独立组件实例，避免复用更早的卡片。外层卡片位置和生成过程中是否挂载由 ChatGPT 宿主控制，插件无法把卡片强行插入宿主原生输入框菜单。


## 可选管理员权限

普通授权留在对话内，仅主动申请 Full Access 才自动弹出面板。要求为当前对话启用 Full Access 和管理员权限时，使用 y_chat_access action=request_full、administrator=true，并指定分钟数。先确认聊天卡片，再在电脑上确认 Windows UAC；模型不能代选 UAC。

管理员命令通过 y_admin_run 执行，每次最长 25 秒，普通文件和桌面工具仍使用普通令牌。取消 UAC 会保留普通 Full Access，但管理员状态为未启用。到期、撤销、关闭上下文或桥接断开后，临时执行器及其 Job 进程树关闭；已完成的修改不会撤销。中断命令的结果可能未知，不得自动重放。当前仅支持同一 Windows 账户提权，重启桥接后需要重新申请。
