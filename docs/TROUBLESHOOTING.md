# Troubleshooting

| Symptom | Meaning and recovery |
| --- | --- |
| Local service not ready | Open Settings from Start, inspect separate local/Tunnel/first-use states. A private Secure Tunnel may wait for a host handshake before creating a Broker. Do not repeat a write of unknown outcome. |
| Saved credential detected | Keep preserves the encrypted value. Test verifies connection status; it never displays the key. Replace is explicit. |
| Runtime key invalid or expired | Replace or rotate the dedicated runtime key locally. The Watchdog stops repeated authentication failures instead of creating new keys or Tunnels. |
| Tunnel permission or workspace denied | Check organization, associated ChatGPT workspace and Tunnels Read + Use permission. Do not switch an unrelated installation's identity. |
| Tunnel already owned | The same data or Tunnel identity has another owner. Close that installation through maintenance only after work is idle. Other Tunnel identities are independent. |
| Session terminated / not initialized | Reinitialize and inspect original operation/job state. Never automatically repeat a mutation. |
| Watchdog task failed | Compare task status with fresh owner health. Last task result alone does not establish live connectivity. Settings can start the owned connection. |
| BACKGROUND_BINARY_MISSING / CHANGED / UNVERIFIED | Inspect Windows Security Protection history and verify the installed manifest. A quarantined or changed daemon is an installation problem, not evidence that the runtime key expired. Update signatures, scan a verified repair package, and repair only if protection permits it. Do not disable protection, add exclusions or repeatedly restore a flagged file. |
| Startup registration missing | With Auto-start enabled, 1.0.22 reconciles only its exact-owner task every five minutes while running. Sign-in and five-minute Scheduler triggers recover an absent process. Explicitly disabled and foreign tasks are preserved. This cannot restore a quarantined executable or a task while no YGPT process is running. |
| STATE_DESCENDANT_ACL_UNSAFE | Inspect the reported path and owner rather than loosening all state permissions. Version 1.0.22 recognizes specific current-user-owned WinGet, pip wheel and embedded WebView caches with their expected system principals. Private root, credential, unknown principal and link failures still require review. |
| Restricted PowerShell script policy | RC3 default state checks and Tunnel inventory use NativeWindows.exe; command classification only parses text. Do not change execution policy. A missing helper requires the full installer. |
| Application folder is not empty | Do not select the extracted portable ZIP folder or an unrelated application's folder. On Welcome choose a new empty destination, typically `%LOCALAPPDATA%\\Programs\\YGPTLocal`. The wizard now checks this before installation, rather than overwriting existing files. |
| Partial installation without watchdog-health.json | Setup now checks for owned running processes before Repair. If none exist it can resume without inventing a health record; if an instance might still be running, it stops and tells you to wait/close that installation safely. Do not manually create `watchdog-health.json` or delete a production Tunnel. On a disposable Windows Sandbox, restarting the sandbox and reinstalling into a fresh directory is a clean test path. |
| Stale or missing health | Status is unknown until the owned Watchdog updates health; absence is not green readiness. Check bundled runtime integrity. |
| Approval pending | Show a fresh card for the original request at the current step, then use bounded `y_wait_approval` while the task stays pending. The decision returns the original result; never repeat the action. If the host cannot mount during a running response, use the same web conversation or the Windows fallback. |
| Android shows tool arguments but no approval buttons | Try `y_preview_approval_ui` and refresh the plugin's tool definitions. Open the same conversation on the web or manually use the Windows Settings approval center under Advanced maintenance. Tokens or a text reply are not approval. Physical Android compatibility still needs client-specific verification. |
| Another device decided, but the chat did not continue | A visible card refreshes saved status. Use Resume chat if its message was not confirmed; this resends only the continuation message. If the phone has no component, return to the same chat after deciding on the PC and request the original saved result. Do not resubmit the action. |
| Opened / CSP off | The outer shell belongs to ChatGPT. Internal approval resources retain CSP metadata. Do not weaken security to hide a host badge. |
| Setup succeeds, ChatGPT not connected | Complete the official personal plugin installation and risk confirmation, then run the wizard's marker task. Local checks do not establish host acceptance. |
| Cleanup waiting | It requires informed consent, authenticated generation-bound marker proof, setup exit and fresh live health. Source Setup deletion has an additional exact-file choice. |
| Cleanup skipped | Inspect the receipt. Changed, linked, open, unknown, referenced or foreign files are preserved. Do not sweep Downloads or Temp. |
| Settings after Setup deletion | Start menu Settings uses the installed verified runtime without the download. Damaged files or version upgrade require a full installer. |
| Maintenance refused | Active work, pending approvals or unknown task state prevent replacement. The application does not kill uncertain work. |
| Both browser profiles are connected but new tabs ask for a profile again | Update to 1.0.7. Keep the contextToken returned by y_browser_attach on the explicit profile choice, open with target=existing, and later browser calls. Profile labels or exact instance IDs select the account. |
| One daily profile times out while the other works | An old YGPT group tab may have stopped answering Chrome debugging commands. Version 1.0.7 bounds each old tab's setup and skips unresponsive tabs without closing them; unavailableGroupTabs reports the count. Healthy group tabs remain usable. |
| Restore conflict | CONFLICT / executed:false / filesRestored:0 preserves later edits. Review the diff; do not repeat the stale restore. |
| Desktop app lacks your login | Tool processes use a sanitized HOME/APPDATA; they are not your normal interactive profile. |
| Tunnel disconnected | Check the connector token, outbound HTTPS/proxy, route and credentials. A Cloudflare connector token cannot create DNS. Do not replace an unrelated tunnel. |
| Authentication failed | Distinguish Cloudflare API token, connector token, OAuth pairing key and Secure MCP Tunnel runtime key. Use the exact MCP resource URL and callback URI. |
| SQLite tool missing | Compare the public catalog with ChatGPT's refreshed plugin tools. `y_sqlite_read` is public; two approval tools are App-only. Refresh the personal connection if needed. |
| Restore conflict | `CONFLICT`, `executed:false`, `filesRestored:0` preserves newer content. Review the diff and restore in the correct order. Do not retry the stale restore. |
| Desktop app has no login | Terminal processes use a sanitized HOME/APPDATA. This is different from your normal interactive app profile. No Windows account switch is implied. |
| "App setup was rate limited" in ChatGPT | ChatGPT is pacing plugin creation. It is not a tunnel or local service failure; the Check step still shows your connection state. Wait a few minutes and create the plugin again with the same values. |
| Check step shows "!" on Connection | Read the row's suggestions. They separate "not running", "running but not ready", key or tunnel ID mismatch, proxy or firewall, and a tunnel already used elsewhere. Run the checks again after each change. |
| Owner approval page says "That key didn't match" | Copy the owner pairing key again from the setup window (Connect ChatGPT, then Copy) and paste it on the same page. If the page says it expired, start the connection again from ChatGPT. |
| Native popup said "请求已过期或已处理" on every click (builds before this fix) | The popup sent the wrong CSRF header name, so the local server refused every decision. This is fixed in `runtime/approval-panel.ps1`. Update, then decide again. |
| Setup retry after partial install | Retain existing files and credentials. The candidate currently refuses in-place overwrite; use a new empty candidate directory. Do not delete snapshots to force a reinstall. |
